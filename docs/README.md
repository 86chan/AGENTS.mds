# docs

設計書運用ガイドライン集。

## 概要

本ディレクトリは、設計書を運用するためのガイドラインをまとめたものです。基本設計・詳細設計・実装設計の3層で管理します。

## 3層構成

| ディレクトリ | 位置づけ | 対象 | ガイドライン |
| :--- | :--- | :--- | :--- |
| `specs/` | 基本設計 | 何をするか（画面・業務仕様） | `specs/Specs.md` |
| `core/` | 詳細設計（言語非依存） | どう実現するか（I/O分離、決定論、DSL、スキーマ） | `core/Core.md` |
| `impl/` | 実装設計（言語固有） | どう実現するか（モジュール構成、クラス割り当て、フレームワーク選定） | `impl/Impl.md` |

基本設計（specs）で「何をするか」を定め、詳細設計（core）で「どう実現するか」を言語非依存に定め、実装設計（impl）で「どう実現するか」を言語固有に写像する。詳細設計は基本設計を、実装設計は詳細設計を前提として導出する。

## ディレクトリ構成

```
docs/
├── README.md
├── COMMON.md         # 共通の記述ルール・運用ルール
├── core/
│   ├── Core.md          # 詳細設計の運用ガイドライン
│   ├── INDEX.md         # 全設計書の一覧と関連（逆引き）
│   ├── DEF-000_用語集.md # 用語集（直下に固定）
│   ├── arch/            # 方式設計書（ARC）
│   ├── interface/       # インターフェース設計書（INT）
│   ├── dsl/             # DSL仕様書（DSL）
│   ├── common/          # 共通仕様書（COM）
│   ├── schemas/         # 機械可読スキーマ
│   ├── tests/golden/    # ゴールデンマスターテストケース
│   └── archive/         # 廃止済み設計書
├── specs/
    ├── Specs.md         # 基本設計の運用ガイドライン
    ├── INDEX.md         # 全仕様書の一覧と関連（逆引き）
    ├── DEF-000_用語集.md # 用語集（直下に固定）
    ├── screens/         # 画面仕様書（SCR）
    ├── business/        # 業務仕様書（BIZ）
    ├── common/          # 共通仕様書（COM）
    └── archive/         # 廃止済み仕様書
└── impl/
    ├── Impl.md          # 実装設計の運用ガイドライン
    ├── INDEX.md         # 全言語の実装設計書の一覧
    └── {lang}/          # 言語ごとの実装設計書群
        ├── INDEX.md     # その言語の実装設計書の一覧
        ├── DEF-000_用語集.md # 技術用語集（直下に固定）
        ├── IMP-001_...md
        ├── {system}/    # 複数アプリ時はシステム単位で分割
        │   ├── INDEX.md
        │   ├── DEF-000_用語集.md
        │   ├── IMP-001_...md
        │   ├── res/
        │   ├── adr/
        │   └── archive/
        ├── res/
        ├── adr/         # ADR（技術選定の詳細比較）
        └── archive/
```

## ファイル命名規則

- 方式設計書: `ARC-{3桁数字}_{構造名}.md`
- インターフェース設計書: `INT-{3桁数字}_{境界名}.md`
- DSL仕様書: `DSL-{3桁数字}_{文法要素名}.md`
- 共通仕様書: `COM-{3桁数字}_{分類名}.md`
- 用語集: `DEF-000_用語集.md`
- 画面仕様書: `SCR-{3桁数字}_{画面名}.md`
- 業務仕様書: `BIZ-{3桁数字}_{業務名}.md`

## 運用の鉄則

- 1文あたり80文字前後を超える文章は禁止（表・コード・URL行を除く）
- 同じ規約を2ファイルに書かない。3ファイル以上に同じ記述が出たら共通仕様書へ移す
- 他文書の内容は再掲せず、IDとリンクで参照する
- 未決事項は明記する。空欄のまま残さない
- 実装の詳細（関数名、テーブル名、API名）は設計書に混入させない
- 設計書を直したら、対応する機械可読スキーマも直す

詳細は `COMMON.md`、`core/Core.md`、`specs/Specs.md`、`impl/Impl.md` を参照すること。
